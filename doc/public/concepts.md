# 理解流与保存

一个实例由主程序管理 Core 和插件。输入插件发布数据，Core 按流组织和提供读取，输出插件订阅流并处理数据。

```text
程序 / 日志文件 / 回放文件
            ↓ 输入插件
          Core 日志流 ──→ CLI / 脚本读取
            ↓
      输出原始字节 / 归档
            ↓（也可选择转换插件）
          派生流 ──→ 读取 / 归档
```

## 插件 ID 和流 ID

插件 ID 标识一个运行组件，例如 `file` 或 `archive`，用于 `plugin call archive ...`。流 ID 标识数据，例如 `logs` 或 `program.out`，用于 `read logs`。一个输入插件可以发布多个流，一个输出插件可以订阅多个流。

`streams` 声明插件可以发布的流，`reads` 声明它可以读取的流；插件 `config` 中的流名必须与这些声明对应。

## 一条记录不一定是一行

输入插件按字节块采集，不要求先遇到换行。Record 包含 `payload` 原始字节、流名、序号 `seq`、身份 `epoch` 和时间等字段。一行可能跨多个 Record，一个 Record 也可能包含多行。

文本处理需要明确编码和分行规则；处理二进制时应按字节理解数据。`read --raw` 连续输出 payload，默认 JSON 读取则保留记录边界和元数据。

## 序号、身份和缺口

`seq` 在一个流的 epoch 内标识记录顺序；`epoch` 用于区分流的不同历史身份。不能把新 epoch 的序号当作旧历史的延续。

读取位置早于可用历史时会报告 Gap。Gap 表示有一段数据无法提供，不是空日志，也不能靠再次读取补造。各流保持自己的顺序，多个流没有统一的全局排序承诺。

## Core 保存和输出归档

| 机制 | 用途 | 需要知道的边界 |
| --- | --- | --- |
| Core 内存缓冲 | 提供近期读取、连接输入和输出 | 有上限，旧记录会被覆盖 |
| Core 保存 | 保留可重新读取的源历史 | 默认关闭；容量有限，不自动删除历史腾空间 |
| `output-raw` 文件输出 | 导出原始字节 | 无持久消费游标，重新追加可能重复 |
| `output-file` 归档 | 写入文件、JSONL、SQLite 并记录提交进度 | 可校验后恢复；依赖源历史仍可重读 |

Core 的 `saved` 只说明 Core 保存状态，不代表归档插件已提交。需要归档插件离线后补齐时，应开启对应流的 Core 保存。

## 转换保留原始流

`output-transform` 读取父流并发布独立派生流，原始父流不被修改。派生记录携带父流进度，便于追溯。转换插件重启可能重新处理历史范围，不承诺跨重启只产生一次结果。
