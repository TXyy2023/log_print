# 性能测量与对照

2026-09-08 在 Apple M1 Max、10 个逻辑核、64 GiB 内存、macOS 26.5 上完成两整轮实测。主表来自其他 UI 验收实例停止后的第二整轮；每场景 12 秒、1000 条/秒、96 字节/条，共 12,000 条、1,152,000 字节。六场景全部字节和顺序一致；保存场景从 Core 历史接口完整回读一致；TUI 消费 12,000 行，零 gap/非法 UTF-8/重复，实际输出到持续排空的 100×30 PTY。

软件为 **1.0.0、Rust 1.92.0 release**；测量时源代码尚未提交，历史 Git HEAD 不是被测版本。每场景结果记录实际可执行文件 SHA256。Python 3.14.1 与隔离环境 psutil 7.2.2 用作发生器/仪器，不在用户全局 Python 安装依赖。

主表中的延迟是原样输出实际写出之后的接收观测，包括绘图并行运行时的原样分支，**不是图表显示延迟**。CPU 与 RSS 包含源 Python 和完整产品/对照进程树；100% CPU 为一个逻辑核，MiB=2²⁰ 字节。

| [tee 文件复制](benchmarks/2026-09-08-macos/tee_save.json) | 0.038 | 0.123 | 0.736 | 6.027 | 4.29 | 31.20 | 93.75 |
| [log_print 持久保存](benchmarks/2026-09-08-macos/log_print_save.json) | 1.024 | 2.083 | 7.464 | 53.228 | 93.29 | 50.47 | 93.75 |
| [tee + 提取器 + ttyplot](benchmarks/2026-09-08-macos/tee_plot.json) | 0.028 | 0.064 | 0.100 | 1.780 | 14.37 | 60.06 | 93.76 |

本机这次原样链路中位数约 0.32 ms，开启保存约 1.02 ms；保存 P99 约 7.46 ms、最大约 53.23 ms，不能宣称所有日志固定在 1 ms 内到达。保存目录实际占用 10,350,964 字节（含记录元信息、SQLite 结构及空 stderr 流），原始负载为 1,152,000 字节。未保存的 Core 有界缓存发生正常旧记录淘汰，在线 Output 未出现数据缺口。

源 write 时间夹的 P99 为 0.022–0.028 ms；仪器自身的 CPU 单列在每个 JSON 中。全机背景 CPU 均值约 16.6%–30.4%（这里按整机计），机器仍有系统/用户背景活动。两轮中的尾延迟差异提醒我们不能用一次短跑构造稳定上界：完整首轮保留在 [背景轮说明](benchmarks/2026-09-08-macos-background/ROUND.md)，主表固定使用第二整轮，不挑选单项最佳值。

TUI 实际生成 8,572 字节终端更新，ttyplot 生成 3,282,830 字节；刷新和差分绘制策略显著不同。产品/对照的完整资源与负载在表中公开，不声称 log_print 比同类工具更省资源。这里提供的是可复现基础结果，尚未测多路规模上限、小时级稳定性、Windows/Linux运行性能与真实串口。另已完成[双UI三分钟持续负载与独立浏览器成本测量](../plugins/outputs/output-webui/SUSTAINED.md)，该报告使用不同输入链路与测量范围，不与本表混算。

## 测法

[`tests/benchmark.py`](../tests/benchmark.py) 启动真实 `log-print` 主进程、Core、input-program、output-raw；绘图再加入独立 output-tui。源 Python 进程按节奏调用 `os.write`，生成带顺序 ID 和数值的固定 96 字节记录。接收端读取 output-raw 实际写出的管道字节，逐条、逐字节及顺序核对，不能以 Core ACK 或 API 事件替代真正输出。

源每次 write 前后分别读取 `perf_counter_ns()`；接收端在 `os.read` 返回后立即读取同一机器的单调时钟。CSV 保留 id、源 write 前/后、接收时间。主表采用 `接收观测 - 源 write 前`，另存 `接收观测 - 源 write 后` 与源 write 时间夹。写入在时间夹内实际发生，但接收观测还包含管道传递和观察进程调度，因此不能将结果称为精确到输出插件系统调用内部的无误差延迟。源 write 后可能晚于接收观测，负值保留用于检查，不偷偷归零。

分别依据实际源写入区间与接收完成区间计算源/输出吞吐，主表使用输出吞吐及核对成功的字节数；目标负载不冒称可持续吞吐上限。每场景使用至少 10 秒，单次运行的 P99 与峰值仅代表该次负载和机器状态。

资源采样使用隔离环境内的 psutil，以 100 ms 等待间隔遍历主进程及递归后代，累计 user+system CPU，记录每组件和整个进程树 RSS。CPU 100% 表示占满一个逻辑核；RSS 总和可能重复计算共享页，不代表唯一物理内存。100 ms 是两次采集间的等待目标，查询耗时另计，实际间隔可从原始时间戳及样本数复核；采样可能漏掉短峰值。源程序计入树总量，并单列，使人能同时看工具成本和完整采集成本。观察器与采样器不计入产品进程树，自身 CPU 单列。

采样器在独立 Python 进程运行。早期脚本冒烟发现同解释器中 psutil 调用占用 GIL 会抬高观察线程尾延迟，因此修正后才采集正式数据。操作系统不提供的每进程磁盘 IO 值记录为空；保存文件实际大小可另核对，不能冒称磁盘物理 IO。记录全机背景 CPU，环境并非独占空闲实验室。

## 对照的范围

- 原样与文件复制采用系统 `/usr/bin/tee`。这是成熟字节复制工具的下限参考，没有 Core、流身份、权限、游标、历史查询或插件管理。Apple 公开的 [tee 源码](https://github.com/apple-oss-distributions/shell_cmds/blob/main/tee/tee.c) 使用 BSD-3-Clause；机器上的实际二进制哈希随结果记录。
- 保存场景中 tee 写普通文件并输出，log_print 执行 SQLite 持久事务、检查与有界保存。tee 不提供同等持久确认/故障恢复语义，不能把二者延迟差解释成相同可靠性下的效率高低。
- 绘图对照采用 [ttyplot](https://github.com/tenox7/ttyplot) 1.7.6（Apache-2.0，源码 commit `533a25e5194897befb8085bc11981f73f05b7368`）。对照树包括相同源程序、tee、提取数值的 Python 进程、ttyplot；原始数据经 tee 的独立管道核对，绘图实际写入 100×30 PTY 并持续排空。
- log_print 同时运行原样 Output 和 TUI，TUI 每 100 ms 刷新，保留 2048 点；ttyplot 按到达数据刷新，保留终端可容纳的点。输入负载和终端大小一致，刷新策略、历史窗口、字体/绘图功能不同；这是相同日志任务的默认配置对照，不能据此宣布同图形工作量下胜负。
- PTY 测量覆盖终端生成与传输，不包含独立终端模拟器渲染成本，不替代肉眼桌面验收。没有外部浏览器参与这六个场景；浏览器成本见独立持续负载报告，真实硬件仍未测。

## 复现

在独立虚拟环境安装 psutil（本次 7.2.2），不要修改全局 Python。`cargo build --release --workspace` 完成且产品代码稳定后运行：

```sh
python tests/benchmark.py --duration 12 --rate 1000 --plot-rate 1000 --ttyplot /path/to/ttyplot --output doc/benchmarks/local --scenario all
```

ttyplot 可从上述官方仓库取指定 commit；本机缺少 pkg-config，采用系统 ncurses 编译 `cc -O2 -DVERSION_STR='"1.7.6"' ttyplot.c -lncurses -lm -o ttyplot`，无需系统安装。上述命令的 `python` 应指向隔离环境。脚本目前需要 Unix 的 pipe/PTY，不宣称 Windows 性能已测。

每个场景保存 `.json` 汇总/配置/二进制哈希、`.latency.csv.gz` 全量原始时间、`.resources.json` 原始资源采样；运行时鉴权 token 不写入结果。程序只清理由其创建的子进程和临时目录。
