## 一、完整首版范围

### R1. 产品、进程和数据关系

- [x] 完成面向 AI Agent 的第一版正式日志工具，以 CLI 易用性为优先，支持人类使用与多人共同维护。“No. 1”是产品愿景，不作为未经比较的宣传事实。
- [x] 一个主进程管理唯一一个 Core 与多个插件，Core 和插件均为主进程的子进程；先启动 Core，再按需启动、停止或重新启动插件。
- [x] 多个 Input 接入同一个 Core，一个插件可产生多条流；各流保留来源标识和流内顺序。
- [x] 支持多个独立 Output；每个 Output 按使用情况订阅同一 Core 的一条或多条流，不扩展多 Core 或跨机器汇流。
- [x] Input/Output 是主要职责名称，不是互斥身份。Output 可消费、处理并作为 Input 将结果发布回同一个 Core，由其他 Output 继续消费；跨插件交互经过 Core。
- [x] 原始流与派生流分别标识，处理不覆盖原始内容；建立防循环机制，允许无环多级组合。
- [x] 插件独立启停、故障和慢消费尽量隔离；说明依赖上游的下游仍可能等待其结果，不能把进程隔离解释为没有任何影响。
- [x] Core 负责通用路由、身份、读取位置、有界缓存、保存、统一读取及状态；业务解析、转换、图表计算由插件负责。

### R2. 保存、读取与实时交付

- [x] 每个 Input 选择是否保存，由 Core 执行保存；可指定保存路径、文件大小等选项，未提供时使用 config 默认值。
- [x] 开启保存时，Output 通过统一接口读取实际保存且仍可用的历史及缓冲数据；未开启时，只读取仍在缓冲区中的数据，不承诺更早内容。
- [x] 区分已接收、已保存、未提交、不可用、已覆盖及缺口等状态；不能把收到请求或进入队列报告为保存成功。
- [x] 无法写入直接报错；之后的处理采用第三区分标明的保守设计默认。
- [x] Input 读到数据后尽快推送，不等换行；允许有明确大小与最长等待上限的小批量合并。
- [x] SDK 统一背压及有界缓冲。保存失败、缓冲覆盖、不可暂停源溢出等均须有可观察反馈，不静默冒充完整数据。
- [x] Output 实时订阅有新数据即交付，不以固定轮询读取实时数据；历史有界批量读取后衔接实时，验证顺序、重复和缺口语义。
- [x] 数据读取与 UI 刷新分开：原样 Output 尽快实际输出，TUI/WebUI 各自独立刷新，不以绘图刷新节奏阻塞采集交付。

### R3. Input 功能

- [x] **程序输出**：采集程序实际输出，覆盖主流语言日志场景；由实现者选择通用可复用的接入方式，一个 Input 可支持多种语言。
- [x] **文件增量**：读取日志文件的新增内容，明确初始读取位置、追加、截断、替换和轮转行为。
- [x] **硬件日志**：提供硬件日志输入，首版只读接收、不发送 TX；实现者合理确定接口、协议、设备范围，记录实测清单。
- [x] **Replay**：提供给定 log 文件的回放插件，将日志模拟为重新产生的数据，经相同发布接口进入 Core；Core 和下游 Output 不需为 replay 改写业务流程。
- [x] 在质量可验证前提下尽量广覆盖并复用成熟能力，不以 Input 插件数量或“全部语言/硬件”未经验证的宣称验收。

### R4. Output 与处理功能

- [x] **原样输出**：字节内容保持一致，数据输出与协议/诊断信息隔离，用于实际使用和端到端延迟验收。
- [x] **进制与编码**：支持二进制等进制表示转换及字符编码转换，区分进制表示与 UTF-8 等 Unicode 编码。
- [x] **自动与手动**：自动识别最可能的编码并反馈不确定性，允许手动选择；具体支持集合由实现者评估成熟库后记录。
- [x] **分行及内容编辑**：提供分行、增加、删减内容的规则配置；这些是业务插件能力，不让原始采集等待完整行。
- [x] 转换、分行或编辑后的结果可作为新流重新输入 Core，下游按统一订阅读取，保留来源且防止循环。

### R5. 独立 TUI/WebUI 绘图与 session

- [x] TUI 和 WebUI 为两个独立 Output 插件，均绘制日志中特定数值参数，同等作为首版前期重点投入和展示方向。
- [x] 两者均支持在线 session，用户进入或选定 session 后，通过 CLI 动态调整对应运行中视图。
- [x] 调整无需重启整个采集链路，不影响其他 session；具体显示参数由实现者设计并记录。
- [x] 两者均提供图表导出，明确导出格式、数据范围和所用视图配置。
- [x] 重点验证动态显示、连续刷新、曲线可读性、多曲线辨识，以及终端/浏览器窗口缩放后的布局适配。
- [x] 分别采用适合 TUI 和 WebUI 的成熟 UI/绘图库。视觉效果优先仅为选型建议，综合鲁棒性、稳定性、维护、跨平台兼容、性能和集成成本，不牺牲数据正确性或运行稳定性。

### R6. IPC、Rust SDK 与复用

- [x] 参考实际成熟方案设计初版 IPC，先交付职责、传输选择、协议消息与错误语义，再实现。
- [x] 先做最小 Rust SDK，用一个 Input 和一个原样 Output 跑通全链路，依据官方插件迭代共性，再扩展插件。
- [x] SDK 封装连接握手、收发、配置读取、错误反馈、退出、背压和有界缓冲；具体接口由实现者拟定。
- [x] 所有插件优先 Rust，官方插件优先基于 SDK，包括 TUI/WebUI；不强制纯 Rust。非 Rust 成熟库明显更适合时可集成。
- [x] Rust 接口、进程通信、前后端分层是可选衔接方式，不预定必须 FFI。可直接复用适配的开源项目或库，记录维护状况、许可证和交付影响。
- [x] 协议是接入标准，第三方可直接按协议实现；Python 等其他语言 SDK 留待后续，不妨碍主流语言日志输入。
- [x] 明确标注初版协议与 SDK，不保证后续兼容第一版；不兼容变更显式升级版本，不兼容接入明确报错。
- [x] 协议定义单 Core 流订阅、发布与派生、防循环、请求响应关联、配置控制、生命周期、历史/实时衔接、资源限制及失败状态，提供样本和可测试契约。

### R7. 配置、CLI 与简易 Skill

- [x] Core 和所有有调节项的插件提供配置入口；默认可直接使用，说明覆盖顺序、每项用途、允许范围和生效方式。
- [x] 尽量覆盖推送、批量、最长等待、缓冲上限、保存、读取和绘图刷新等有用调节项。
- [x] 安全可动态调整的参数通过 CLI 运行时调整，否则静态配置或重启生效；TUI/WebUI session 显示动态控制是明确必做。
- [x] CLI 覆盖启动、插件启停、流/状态查看、读取、配置查看与修改、session 选择与显示调整、图表导出及停止流程，具体命令由实现者设计。
- [x] 配套简单 Agent Skill，仅包含用途、常用命令及“启动采集 → 读取 → 停止”的最小完整示例，不做复杂编排。

### R8. 验证、文档、目录与交付

- [x] 覆盖 macOS、Linux、Windows；优先在本地 Mac 尝试运行适用的 GitHub Actions/self-hosted 流程，线上 GitHub Actions 作为回退与补充。
- [x] 本地 macOS 不能替代 Windows/Linux 运行验证；记录每个平台的构建、实际运行、CI、UI 和硬件验证边界。
- [x] 测量源端实际输出到原样 Output 实际输出的同条日志 delta，核对内容；报告典型及尾部延迟、流量、路数与保存配置，尽量争取毫秒级，首版无固定门槛。
- [x] 测量整个进程树及 Core/插件分项 CPU、内存、吞吐、延迟，必要时磁盘 IO；与同类日志/串口工具作等价场景实测比较，不要求极低占用或优于同类。
- [x] 完善 README、正式架构/协议、目录入口、插件/SDK 使用说明、协作和贡献流程，使新维护者可复现开发与验收。
- [x] MVP v1/v2 源码与相关阶段文档完整本地归档，位置在 doc 外，归档不进入新的 Git 提交；重要正式架构等文档进入 Git。
- [ ] 正式版完成后检查待交付内容，再按后续执行范围提交并推送到 `git@github.com:TXyy2023/log_print.git`。既有历史保守保留，不擅自清洗历史或强推。

### P2. 最小可运行链路

- [x] 实现主进程、唯一 Core、Rust SDK、一个 Input 和原样 Output，建立真实子进程链路。
- [x] 实现基础 config/CLI、先启动 Core 后启停插件、状态及错误反馈、正常退出回收。
- [x] **交付/验收**：可运行示例与进程级脚本；发送已知字节、无换行及拆包样本，核对实际 Output 内容；验证版本拒绝、启停、错误与无残留子进程。

### P3. 多流、可靠读取与插件集合

- [x] 实现多 Input、多流、单/多流订阅、多个 Output、Core 保存及统一历史/实时读取。
- [x] 完成程序输出、文件增量、硬件只读与 replay；按覆盖矩阵用真实来源验证可复用接入。
- [x] 完成编码/进制转换、分行和内容增删，发布派生结果，打通多级处理。
- [x] 实现有界背压、缓存覆盖反馈、写入失败默认行为、连接恢复与持久数据回读。
- [x] **交付/验收**：插件说明、样例、契约及故障注入脚本；验证多流隔离与顺序、慢消费者不拖住独立分支、单流和多流订阅、防循环、历史转实时无额外遗漏/重复及明确缺口。
- [x] **输入验收**：文件追加/截断/替换；无换行程序输出；串口PTY只读链路（Linux实际通过，macOS驱动ENOTTY明确跳过）；同一回放文件经统一链路内容一致，Core/Output 无 replay 专用业务分支。
- [ ] **物理硬件验收**：真实串口设备只读接收、设备/驱动记录。当前没有适合的实物测试设备，保留未验证，不将PTY当硬件通过。
- [x] **保存验收**：按 Input 开关及参数覆盖、重启后可用历史、未保存数据缓冲范围、磁盘不可写/容量不足、断连及故障后手动恢复；按第三节默认检查状态，不声称模拟故障等于断电/坏盘验证。
- [x] **转换验收**：已知/未知编码、非法字节、手动覆盖、进制往返适用范围、跨块分行、增删规则；原始流保持不变。

### P4. TUI/WebUI 绘图与在线控制

- [x] **交付/验收**：两个可运行绘图例子、命令示例、导出样本、终端/浏览器记录；独立启停可用。
- [x] 指定 session 动态调整在对应已打开视图及时可见，其他 session 不变且采集链路不中断。
- [x] 验证连续刷新、窗口缩放、多曲线辨识、空数据/异常数据以及导出可打开、数据范围与视图配置一致。 已验证真实Chrome及POSIX PTY，实际可见终端另列未验证。
- [x] 测量高流量与持续运行下刷新、调整延迟、CPU/内存；显示效果与资源指标报告实值，不预先承诺“完美”。 已测180秒、1000行/秒、周期Canvas/数据进度、CLI往返及两棵资源树；100ms仅为刷新配置，未精确测屏幕FPS或采集到屏幕延迟。

## 三、实现者设计默认及理由

以下是为开工消除悬置问题的建议默认，不是用户逐项指定的技术参数。P1 记录最终采用值、理由和可配置范围；变更默认须同步文档与验收。不得由此引入破坏性历史改写或扩大首版范围。

| 项目 | 建议默认与边界 | 理由及生效方式 |
|---|---|---|
| 保存开关 | 默认不保存，按 Input 显式开启；CLI/status 明确提示当前仅缓冲或已启用保存 | 避免隐式无限写盘；开关建议重启该 Input 生效，明确新保存区间 |
| 保存成功 | 开启保存的发布在持久提交后才报告保存成功；提交结果不明时标为未知，不能报告丢失或成功 | 防止假确认；重复恢复的身份/幂等规则在协议中定义 |
| 无法写入 | 立即报错，停止接受受影响的需保存流的新发布并反压来源；其他独立流继续。修复后由 CLI 手动恢复，不自动降级为不保存 | 局部保守失败，避免静默丢数据；是设计默认，不是看门狗 |
| 不可暂停源 | 有界缓冲耗尽时记录溢出/缺口与可获得的计数、位置；无法知道缺失量则明确未知 | 硬件只读不保证可反压，禁止虚构无损 |
| 缓冲及慢端 | 未保存流使用有界近期环形缓存，满后淘汰最旧数据并报告覆盖范围；慢 Output 超出范围得到缺口。已保存流从仍可用历史补读 | 有界资源与独立消费；条数/字节限制由 P1 实测设定 |
| 文件上限 | 区分单文件与每流总保存量；默认到上限报错，不自动删除历史；轮转仅在总量内创建新文件 | 不擅自破坏数据；路径/单文件/总量配置，默认值在 P1 明示 |
| 派生与顺序 | 原始/派生流独立 ID，声明父流并拒绝环；保证流内顺序，不默认承诺跨流全局时间排序 | 支持组合且避免循环；流关系修改先校验 |
| 推送与批量 | 默认读到即推；可配置有限批次和最长合并等待，不等换行 | 保持低延迟，具体值按 P2 测量；安全参数允许 CLI 动态调整 |
| 参数变更 | 优先级为内置默认 → 配置文件 → 启动参数 → 会话运行时覆盖；运行时修改默认不回写文件。连接、身份、存储路径等变更建议重启，安全显示项动态 | 可解释、避免隐式持久修改；CLI 显示最终值及来源 |
| 文件与程序输入 | 程序 stdout/stderr 分来源；文件默认从启动时末尾跟随，可选从头。截断/替换开新流段并反馈，不假装连续 | 通用多语言复用；源覆盖和边界有记录 |
| Replay | 有可解析时间信息时按原间隔回放；无时间信息时采用可配置固定节奏并明确“模拟节奏”。每次新运行标识，保持原始负载 | 下游透明但不伪造时间；速度等参数由实现者定义 |
| 编码与编辑 | 自动识别低置信度保留原始字节并提示，允许手动覆盖；内容增删只产生派生流，不修改源文件 | 原始证据不丢失；规则和编码可安全动态时开放 CLI |
| 图形默认 | 每插件 session 独立显示状态；曲线选择/时间窗口为候选动态项；导出建议优先 PNG，可依图库补 SVG。WebUI 默认仅本地访问 | 可用且范围有限，不扩展托管/多人认证；格式在 P1 定案 |
| 故障与关闭 | 插件异常退出明确状态，不自动重启；正常关闭有界等待并报告未完成数据。仅回收本实例拥有的进程 | 首版无看门狗；恢复手动、状态诚实 |
| 平台与规模 | 先验证小规模正确性，再扩大路数/流量与时长；每次记录实值和环境，不虚构统一性能门槛 | 以证据形成默认配置和支持范围 |
